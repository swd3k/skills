# Product Docs Page

## Structure
1. What it is (1–2 sentences)
2. Who it's for / requirements
3. Quick start (shortest happy path)
4. Features / usage
5. Troubleshooting
6. FAQ
7. License / links

## Writing
- Commands in copy-paste blocks
- Screenshots near the step they illustrate
- Callouts for warnings (admin, data loss)
- Keep version-specific notes dated

## README for desktop tools
- Badges optional; size and platform clear
- Install → first run → elevate notes
- Link to releases, not only source

## Acceptance
- New user succeeds from docs alone on a clean machine
